## Caption

A long project list does not always help a fresher.

Sometimes it slows the recruiter down.

In the first resume scan, the hiring team is usually not asking:

How many projects has this student done?

They are asking:

Which project proves this student can handle this internship?

That is a different question.

One relevant project can create more trust than five unrelated ones.

Especially when the project line clearly shows:

- the role skill used
- the problem solved
- the tool or method applied
- the result or learning

The mistake is writing every project with the same weight.

A calculator app, a dashboard, a landing page, and a college assignment can all sit on the resume.

But only one or two may connect strongly to the role.

Those should be easier to notice.

Before applying, do a simple check:

If a recruiter reads only my top project line, will they understand why I fit this internship?

If the answer is no, rewrite that line before adding another project.

Relevance is the signal.

Count is only supporting context.

What do you think freshers should show first: more projects, or one project explained clearly?
