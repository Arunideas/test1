## Caption

A resume line can say what you did.

Or it can show why a recruiter should trust you.

Those are not the same.

Many freshers write project and internship bullets like this:

Worked on user authentication.

Created dashboard screens.

Used Python for data analysis.

These lines are not wrong.

They are just incomplete.

In a fast scan, the recruiter is trying to answer one practical question:

Can this student turn a task into visible output?

So the stronger line usually has four parts:

- action
- scope
- tool or method
- proof

Not a big claim.

Just enough evidence.

For example:

Built a login flow for a student portal using Next.js and form validation, making sign-up errors easier to catch during testing.

That line gives the recruiter something to hold.

The role skill is visible.

The context is visible.

The outcome is visible.

Before sending your resume, pick one important bullet and ask:

If this was the only line a recruiter read, would it show useful proof?

If not, rewrite the line before adding another certificate or project.

A short proof line can do more than a long responsibility list.

What part of a resume bullet do you notice first: the action, the tool, or the result?
